# Windows network-on scripts have their own container

Network-on scripts run in a second profile, `aicadscriptnet`, which the block does not name. Taking the block down for one run needed administrator rights, and an administrator's run left the computer half blocked. Folder grants are per container, so the first network-on run in a process walks the Python folders again. A script of either kind still needs setup to have run, so there is one rule to explain.
