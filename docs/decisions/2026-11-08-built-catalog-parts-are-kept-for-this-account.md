# Built catalog parts are kept for this account, not in the project

Every open of a project built each catalog part again, and a ball bearing fuses its balls to the races one at a time, so the two bearings of a 38-part finger rig were 2 of its 5.5 seconds to open; a built catalog solid is now written in OpenCascade's exact BREP format to `~/.config/aicad/catalog`, or `$AICAD_CATALOG_CACHE`, under a key made of the request and a fingerprint of the catalog code and the build123d, bd_warehouse, and OpenCascade versions, and the next build of the same request reads it back, which brought the open to 3.5 seconds. The folder is this account's, beside its other aicad files, and not the project's: a project is shared, and a file in it named for a catalog request could stand in for a bearing or a screw with other dimensions. A changed definition gets a new key, so an old solid is never used for it; a file that cannot be read is built again; and a folder that cannot be written only means the part is built each time. The test suite points the folder at a temporary one for each run.
